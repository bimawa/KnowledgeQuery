# Product Steering: kqs — Git-native Knowledge Platform

## Product Vision

kqs — CLI-инструмент для управления знаниями и документацией в Git + markdown.
Синхронизация, поиск (полнотекстовый + векторный), AI-помощь, трекинг задач
и **трассировка зависимостей** между документацией и кодом —
всё в одном бинарнике, без серверов и баз данных.

Obsidian (или любой markdown-редактор) — интерфейс для чтения и редактирования.
kqs решает то, чего нет в Obsidian: multi-repo sync, кросс-репозиторный поиск,
AI из CLI, управление задачами, авто-обновление README
и **глубокая трассировка** требований до кода.

## Target Users / Personas

- **Разработчик:** Пишет документацию, работает с поиском, AI-запросами,
  тасками, git-синхронизацией и аннотациями кода (`@doc-anchor`) через CLI.
- **Не-разработчик (PM, аналитик, дизайнер):** Читает и редактирует .md файлы
  в Obsidian. Никогда не трогает CLI.
- **Tech Lead:** Управляет задачами (`kqs task`), видит статус команды
  через README-канбан и **матрицу трассировки** на главной странице репозитория.
- **QA / Compliance:** Проверяет покрытие требований кодом и тестами
  через `kqs check traceability --deep`.

## Value Proposition

- Zero инфраструктуры: установил бинарник → `kqs init` → работаешь
- Знания рядом с кодом: docs и tasks в Git, не в Notion/Confluence
- Поиск без API-ключей: семантический поиск работает полностью офлайн
- README всегда актуален: канбан-доска и статусы задач обновляются автоматически
- **Трассировка без боли: kqs сам находит сирот и битые ссылки между docs и кодом**
- Любой участник работает в удобном редакторе — это просто .md файлы

## Product Boundaries

### In Scope

- CLI + background daemon (watcher)
- Управление knowledge-репозиторием (`kqs init`, структура, конфиг)
- Авто-коммит изменений (watcher), ручной push (`kqs push`)
- Полнотекстовый поиск (FTS5) и векторный поиск (sqlite-vec + Candle)
- AI-чат из CLI (опционально, через внешние LLM)
- Трекинг задач в Git (один файл = одна задача)
- Генерация README с канбан-доской
- Multi-repo watcher (следит за knowledge-репозиторием и проектами)
- **Граф трассировки: SQLite-база связей docs ↔ code**
- **Deep coverage: проверка полных цепочек требований (BFT→ADR→TZ→code)**
- **Code anchors: @doc-anchor в исходниках, cross-repo сканер**
- **Revision tracking: stale-детекция при изменении документов**
- История изменений и diff (`kqs log`, `kqs diff`, `kqs blame`)
- Обработка Git-конфликтов
- **Trace daemon: фоновый re-index и orphan alerts**

### Out of Scope

- Web UI / REST API (Obsidian и есть UI)
- Полноценный документооборот (маршруты согласования, подписи)
- Гранулярные права доступа (Git-уровень)
- Мобильное приложение
- Real-time коллаборация (асинхронная модель через Git)
- Obsidian-плагин (опционально в будущем)

## Success Metrics

- Single binary — установил и работает
- Векторный поиск без единого API-запроса (CPU, локально)
- README проекта всегда отражает актуальное состояние задач
- **Cross-repo trace: обнаружение сирот в docs и коде за <1s на 1000+ документов**
- **Deep coverage: верификация полных цепочек (BFT→ADR→TZ→impl)**
- Никаких внешних сервисов для базового функционала

## Domain Glossary

- **knowledge.toml** — конфигурационный файл kqs
- **kqs** — название CLI-утилиты (пакет `kqs` на crates.io)
- **Watcher** — модуль отслеживания файловой системы
- **sqlite-vec** — SQLite extension для векторного поиска
- **Candle** — HuggingFace ML фреймворк на pure Rust
- **all-MiniLM-L6-v2** — модель эмбеддингов (~80 МБ, CPU)
- **Trace Graph** — SQLite-граф связей документов и кода
- **Code Anchor** — аннотация `@doc-anchor <name>` в исходниках
- **Deep Coverage** — проверка полной цепочки требований (не только прямой ссылки)
- **Revision** — версия документа для stale-детекции
